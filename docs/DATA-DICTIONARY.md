# 巡检原件与规则

## 源文件

| 档件 | 主字段 | 定义 |
|---|---|---|
| `campaign.json` | `code`, `version`, `seed`, `groups`, `start_utc`, `end_utc`, `penalty_cents` | 档案版本、抽签种子、正整数店组权重、账期与罚则 |
| `stores.csv` | `store`, `group`, `timezone` | 字符串门店编号、分层店组、IANA 时区 |
| `slots.csv` | `store`, `slot`, `category` | 定义一柜一个抽样单位，分类用于匹配陈列图 |
| `visits.csv` | `visit`, `store`, `clock` | 巡检编号及发生时间，允许带偏移或按门店时区解释本地时间 |
| `plans.csv` | `plan`, `category`, `start_utc`, `end_utc`, `sku`, `facings`, `price_cents` | 单柜单应陈商品的版本窗口、最少排面、规定价签 |
| `aliases.csv` | `alias`, `sku` | 商品旧名到当前编号，可跨多跳，循环与归属冲突整批拒绝 |
| `photos.csv` | `photo`, `visit`, `slot`, `file`, `captured` | 原件编号、柜位绑定、拍摄时刻，`file` 关联 `photos/` 中的 PNG |
| `observations.csv` | `visit`, `slot`, `photo`, `kind`, `sku`, `facings`, `price_cents` | 人工清点明细，`ITEM` 给商品、排面和价签，`COMPLETE` 标记清点完毕且商品列须空 |
| `filings.csv`（可选） | `filing`, `store`, `slot`, `plan`, `sku`, `facings`, `price_cents`, `start_utc`, `end_utc` | 总部备案的替代品：绑定唯一门店、唯一柜位和一版陈列图，给出替代商品的最低排面与规定价签及有效期 |

`source` 保存文件名、起止物理行号及逐列原值。UTF-8 BOM、UTF-8 与 GB18030 按文件识别。空白、表头、逻辑记录分别统计。目录源文件被读取到有大小上限的内存快照，单表 512 KB，每张 PNG 128 KB，每档最多 256 张。编号以字符串保存前导零。数字接受全角和标准千分位，禁止缺价、负价与科学记数法。金额与价签均用整数分，界面显示元。

## 时间、生效陈列图和商品

账期与陈列图时间区间左闭右开。带偏移和门店本地时刻统一为 UTC。遇夏令时重复或跳过的本地时刻，隔离该巡检行；显式偏移可唯一确定时刻。门店当期有多次有效到访时，用时间最新的一次，同时间用巡检编号降序确定。保留其余到访的源行与替代记录。

一个柜位按分类和有效巡检时点匹配一版。匹配零版、同一时点重叠，或命中归属冲突的版本编号时，单柜隔离并列出候选。重叠本身允许出现在版本表；只有相交窗口内的柜位受影响。商品旧名先规范化字形，再解析至最终 SKU。完全相同的主键记录保留首个物理行，其余隔离。同主键不同事实整组隔离。

## 替代备案

备案不是陈列图：它只回答「这一柜缺了应陈商品时，总部批准用哪个替代品顶上」。一条备案绑定一个门店、一个柜位、一版陈列图和一个有效期区间，任一不符都不能抵扣。有效期左闭右开，按采信巡检时点判定。备案行引用未登记的陈列图、未登记的门店或柜位、倒置区间或格式错误时整行隔离；同一 `filing` 主键的副本必须一致，矛盾副本全部隔离，不会静默挑一条。

逐柜核对只有五道门全部通过才抵扣缺品：备案版本＝该柜巡检时点生效的陈列图；巡检时点落在备案有效期内；该柜图证已核且清点完成（待证或隔离都不能抵扣）；应陈商品确实不在架；备案替代品在清点里真实出现，且排面不少于备案、价签等于备案。抵扣只抵 `MISSING_SKU`：替代品不算 `WRONG_SKU`，但同柜其他陈列图外商品、应陈商品排面不足和价签不符照常开罚。应陈商品已经在架时备案不生效（`FILING_NOT_REQUIRED`），也不会产生负数罚额。

逐柜输出备案号、结论码、备案柜位、备案依据版本及其陈列图源行、实际生效版、替代是否上架和实见替代的排面价签。跨店或跨柜位的同商品备案只在「不能抵扣的备案」里列出，永远不参与抵扣。工作台显示应罚额、备案抵扣、原罚额、异议减免和结算净额，四者勾稽。没有 `filings.csv` 的原件按零抵扣处理，不会默认放过。

## 图证、抽样和罚额

照片接受符合大小约束且基本 PNG 段与 CRC 正常的原件。对应巡检时间向前或向后最多 30 分钟，刚好等于上限有效。SHA-256 基于文件字节，换文件名不会改变摘要。任一摘要绑定到不同的 `(巡检, 柜位)` 时，该组图证隔离，包含未抽中柜位的绑定。同柜同巡检的相同照片只表示重复支持。原件可通过批次文件摘要复核，服务回读会拒绝与摘要不同的现有文件。

抽样先按店组权重以最大余数分配目标，余数并列用组编号顺序。组内按 `SHA-256(种子 + NUL + 门店 + NUL + 柜位)` 排序抽取，哈希并列用柜位键。名册供给不足在本组登记缺额，保持未到访和缺证柜位的抽中身份。有效缺口＝目标－可核。它包含待证、隔离和名册缺额。

缺有效照片或缺清点完成标记分别待证；当相同商品的多条有效照片清点结果互相矛盾，冲突行和柜位均隔离。若图证因冲突或复用而失效，且该柜位没有额外有效材料，柜位隔离。只有陈列图唯一、图证有效、录入无冲突且清点完成才可判缺品。`MISSING_SKU`、`WRONG_SKU`、`UNDER_FACINGS`、`PRICE_MISMATCH` 保留所有命中项和证据；同柜只取金额最高的一项，同分按上述顺序。罚额以原始整数分求和。

## 运行、勾稽和异议

输入行号多重集＝采信行号＋隔离行号。目标＝实际抽中＋名册缺额；实际抽中＝合规＋违规＋待证＋隔离。原罚额＝各柜执行罚额＝各店组原罚额之和。结算净额＝原罚额－已裁定减免。

运行键用全部源文件与照片 SHA-256、有效参数、规则版本生成（有备案时含 `filings.csv`），SQLite 原子保存完整快照。异议事件只追加，柜位状态从未发起到 `OPEN`，再到 `UPHELD`、`WAIVED` 或 `REDUCED`。`expected_version` 从 0 开始。完全相同的 `request_id` 和内容可重放，键复用但内容不同返回 409。部分减免必须大于 0 并小于原罚额；全减使用 `WAIVED`。每条事件带经办人、说明、依据编号、原罚额、原罚则和陈列图源行。

已生成批次连同备案行、逐柜结论和抵扣金额一起存进快照，源文件之后再改也不影响当时依据；同一运行键重跑取回同一批次，不会把同一条备案抵扣两次。生成失败（含备案档件损坏）不写入任何快照，旧批次原样保留。

随项目附合成货架缩略原件以演示字节查重。通过人工清点表判断商品，未做图像识别、感知重复、EXIF 验真、在线上传、后台身份认证或记账系统回写。证据包包含照片摘要而无需重复打包图片字节，清点表与原始字段一并留存。
